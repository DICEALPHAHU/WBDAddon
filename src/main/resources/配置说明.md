# WBDAddon 配置说明

> 这份说明随插件一起打包，首次启动时会释放到 `plugins/WBDAddon/配置说明.md`。
> 它比 `config.yml` 里的注释更完整：讲清每个模块**为什么**要这么配、**什么情况下需要改**，
> 以及换一台服务器时需要重新核对哪几处。

---

## 一、安装与依赖

| 项目 | 要求 |
|---|---|
| 服务端 | Paper / Spigot / Arclight 1.20+（已在 Arclight 1.20.1 Forge+Bukkit 混合端实测） |
| Java | 17+ |
| 硬依赖 | **WarZBombDefuse**（没有它插件不会加载） |
| 软依赖 | **TacZSpigotBridge**（枪械相关功能需要；缺失时 `loadout-guard` 自动跳过，其余模块照常工作） |
| 可选 | PlaceholderAPI、JourneyMap、WBDTeamDeathmatch |

`plugin.yml` 里已经把 WarZBombDefuse 写成 `depend`，所以不用手动排序加载。

## 一之二、目录结构

```
plugins/WBDAddon/
├── config.yml            # 主配置
├── item-categories.yml   # 分类对照表（类别开关 / 落点 / 顶不顶掉）
├── weapon-names.yml      # 武器名转换表
├── 配置说明.md            # 本文件
└── data/                 # 运行时数据，会自己增长
    ├── stats.db          # 比赛历史 + 生涯数据 + 最近结果（SQLite）
    ├── stats.yml         # 同上的 YAML 备份，也是驱动缺失时的回退
    └── position-backup.yml
```

**数据存储**：优先写 SQLite（`data/stats.db`），驱动缺失时自动退回 YAML，行为完全一样。
驱动不打包在插件里——Paper / Spigot / Arclight 的 `libraries/` 自带 `org.xerial:sqlite-jdbc`；
如果服务端确实没有，日志会明确写「未找到 SQLite 驱动…继续用 YAML」，不会报错。

- 配置留在根目录，方便随时改；数据统一收在 `data/`，根目录不会越长越乱
- 从旧版本升级时自动迁移：`menu-results.yml` / `player-stats.yml` 会合并成
  `data/stats.yml`，`position-backup.yml` 会搬进 `data/`，旧文件改名 `.bak` 留底
- 想清空数据就删 `data/` 目录；不会影响配置

## 二、模块总览

所有模块都在 `config.yml` 的 `modules:` 下面，每个都有 `enabled: true/false`，
改完执行 `/wbdaddon reload` 生效，不需要重启服务器。

| 模块 id | 名称 | 一句话 |
|---|---|---|
| `kill-reports` | 击杀报告 | 替换淘汰消息，回合结束给每人发自己的伤害统计 |
| `match-status` | 比赛状态显示 | 顶部显示双方存活人数；下包后 BossBar 倒计时 |
| `bomb-defuse-sound` | 拆弹声音提示 | 拆弹过程播放带方位的滴答声 |
| `arena-food` | 竞技场饥饿锁定 | 饥饿恒定，跑速稳定、不自然回血 |
| `arena-effects` | 药水效果清理 | 进场 / 每回合清空药水效果 |
| `position-backup` | 进场位置兜底 | 记录进场前位置，重启后补传 |
| `arena-drops` | 阵亡掉落 | 阵亡掉枪，C4 可落地 |
| `team-armor` | 队伍护甲 | 染色皮革甲做阵营区分，护甲值抵消为 0 |
| `loadout-guard` | 装备槽守卫 | 武器分类 / 限购 / 固定槽位 / 购买兜底 / 开商店按键 |
| `freeze-countdown` | 冻结倒计时音效 | 冻结最后几秒的「哒」声 |
| `menu` | 主菜单 | `/wbda` 或 Shift+F 的箱子菜单 |
| `vote` | 比赛投票 | `/vyes` `/vno` 表决，四种投票事项 |
| `spectate-camera` | 观战第一视角 | 阵亡后跟随存活队友视角，`/spectate` 手动切换 |
| `name-tag` | 昵称标签 | 队友看得见名牌、敌人看不见（逐人按计分板控制，替代 WarZHideName） |
| `teammate-glow` | 队友轮廓发光 | 只对同阵营显示队友轮廓，敌人看不到（需要 ProtocolLib） |
| `short-handed-compensation` | 少人经济补偿 | 从第 N 回合起，人数少的一方每人每回合补一笔钱 |
| `reconnect` | 断线重联 | 掉线守下一回合，重连继承数据 |
| `round-events` | 回合事件 | 回合开始清场、上半场最终局、赛点提示 |
| `round-summary` | 回合结算展示 | 胜方 + MVP + 回合趣闻 |
| `technical-pause` | 技术暂停 | `/pause` 和 `/wbdaddon pause` |
| `journeymap-bridge` | JourneyMap 桥接 | 队伍同步到原版计分板队伍 |

## 三、换一台服务器时，**必须核对**的几处

插件本身不写死任何具体物品，全部按 WBD 的 `shop.yml` 和 TacZ 的分类来跑。
但下面三处和服务器环境相关，换环境时最容易出问题。

### 1. 武器分类（`loadout-guard`）

模块按**类别**工作：主武器 / 副武器 / 近战 / 投掷物。
类别来源按优先级：

1. **`item-categories.yml` 分类对照表**（腐竹可编辑，优先级最高）
2. 物品上的 WBDAddon 标签（PDC `loadout`）——认过一次就固定
3. TacZ 的 GunId → TACZ index 里的 `type`（pistol / rifle / sniper / melee …）
4. config.yml 里的旧规则（`gun-overrides` / `*-materials`）作为兼容兜底
5. 都没命中 → 默认 `primary`，并在控制台提示一次

### 分类对照表 `item-categories.yml`

首次启动自动生成，内容抄自当前 `config.yml`，之后**以它为准**。四张表，先命中先用：

```yaml
# 按 TacZ GunId（大小写不敏感，可省略命名空间）
guns:
  "tacz:some_knife": melee

# 按物品显示名（去掉颜色码后比较），适合非 TacZ 物品
names:
  "战术刀": melee

# 按 Bukkit 材质
materials:
  LRTACTICAL_THROWABLE: throwable

# 按 TacZ index 里的 type 兜底
types:
  pistol: secondary
  rifle: primary
```

可选值：`primary` / `secondary` / `melee` / `throwable` / `utility`（不限购）/ `none`（不纳入管理）。
改完 `/wbdaddon reload` 生效，已经打过标签的物品也会因为「对照表优先」立刻改判。

不知道自己商店里有哪些枪？执行 `/wbdaddon shopscan`：

- 逐条列出 `商品ID | GunId | TACZ type | 当前分类`（控制台也会打 `[shopscan]` 前缀的日志）
- 末尾直接给出可粘贴的 `guns:` / `names:` 片段
- 只读，不会改动任何文件

### 类别开关与落点

同一张表顶部的 `categories:` 段落决定「这个类别管不管」和「它占哪一格」：

```yaml
categories:
  primary:
    enabled: true      # false = 这个类别完全不管理
    slot: 0            # 落点：0-8 是快捷栏
    on-buy: replace    # replace = 顶掉手里那把；block = 已有同类就拒绝购买
    same-gun: inherit  # inherit = 沿用全局 same-gun-policy；replace = 同款也顶掉；block = 同款拒绝
    refund-old: true   # 顶掉时是否退还旧武器的商店价
  secondary:
    enabled: true
    slot: 1
    on-buy: replace
  melee:
    enabled: true
    slot: 2
    on-buy: replace
    same-gun: replace  # 刀不要钱，同款也直接换
    refund-old: false
  throwable:
    enabled: true
    slot: 3
    limit: 4           # 投掷物总颗数，0 = 不限；其余三项固定 1，写大也不放宽
```

**顶不顶掉由你自己决定**：

| 配置 | 买同类新武器（不同枪） | 买同一把枪 |
|---|---|---|
| `on-buy: replace` + `same-gun: inherit` | 顶掉旧的，旧枪按商店价退款 | 按全局 `same-gun-policy` |
| `on-buy: replace` + `same-gun: replace` | 顶掉旧的 | 同款也顶掉（不退旧枪，防免费补弹） |
| `on-buy: block` | 已有同类就**拒绝购买并退款** | 同上（拒绝） |

`refund-old: false` 则顶掉旧武器时不退钱（刀就是这样配的）。

- `enabled: false` → 该类**不锁格子、不限购、不替换、不拦截拾取**，完全交还给 WBD 原生行为
- `slot` 四项必须互不相同，也不要和 WBD 的 `c4-slot`（默认 4）、商店开物品槽位（默认 8）撞车
- 不写这一段（或删掉）就沿用 `config.yml` 的 `slots` / `limits`，老配置不用改
- 启动日志会直接列出当前落点，并在关掉某类时标注「（已关闭）」

分类结果会写回物品本身（`primary` / `secondary` / `melee` / `throwable` / `utility`），
所以同一把枪不会因为 TacZ 升级、`gun-overrides` 改动而忽然换类别。
标签是「认一次就固定」的，万一认错了（比如先打了标签、之后才补 `gun-overrides`），
用 `/wbdaddon retag` 把背包里的标签洗掉重新分类即可。

**常见坑**：很多近战模组把刀做成 TACZ 枪械，index 里的 `type` 却是 `sniper`，
于是被当成主武器，买刀不会替换、也锁不到第 3 格。
解决办法是在 `item-categories.yml` 的 `guns` 里补一条：

```yaml
guns:
  "tacz:some_knife": melee
```

不知道 GunId 的话，打开 `modules.loadout-guard.debug: true`，买一次就会在日志里
打出它识别到的类别，照着补即可。

### 2. 商品落点（`give-slot`）

WBD 的 `shop.yml` 里每件商品可以写 `give-slot`：

- `give-slot: -1`（大多数商品）→ `addItem` 发放，**背包 36 格全满时物品会被丢弃**
- `give-slot: 0~35` → 直接 `setItem` 覆盖那一格，**原本在那格的东西会消失**

两种情况钱都已经扣了。本插件的 `purchase-safety` 会在扣钱瞬间抓背包快照，
事后发现东西没到手就按比例退款、落点格被顶掉就把旧物品还回去。
**这个兜底对所有 `shop.yml` 通用**，不需要按商品配置。

### 3. 内部字段反射（`technical-pause` / `reconnect` / `vote`）

以下功能依赖 WBD 的内部实现，WBD 大版本升级后可能失效（失效时只会降级，不会崩服）：

| 功能 | 依赖 |
|---|---|
| 技术暂停 / 断线等待冻结回合计时 | `ArenaSession.tickTask` 字段 |
| `/vsdr` `/vmap` 提前结算 | `ArenaSession.endMatch(Team)` 方法 |

启动日志里会明确写「计时器会一起冻结」或「提前结算不可用（反射失败）」，
看到降级提示就说明 WBD 换了实现。

## 四、`loadout-guard`（装备槽守卫）重点说明

这是配置项最多、也最容易被问到的模块。

### 基本规则

- 主武器 / 副武器 / 近战各 1 把，固定到 `slots` 指定的三格
- 投掷物按 `limits.throwable` 限购（默认 0 = 不限），固定到第 4 格
- `slots` 四项必须互不相同，且不要和 WBD 的 `c4-slot`（默认 4）、
  商店开物品槽位（默认 8）撞车，启动时会警告

### 同款与替换

| 场景 | 默认行为 |
|---|---|
| 买同类**不同**武器 | 旧武器按商店价退款，新武器进固定槽 |
| 买同类**同一把**枪 | 取消购买并退款（防止用「买同一把」免费补弹） |
| 买刀 | **直接换掉手里那把**，不退款、不拦截（刀不吃弹药，`melee-always-swap`） |

`same-gun-policy` 可改成 `replace-no-refund` / `replace-refund`。
刀的行为由 `melee-always-swap` 单独控制，设成 `false` 就退回和枪一样的规则。

### 预留格子（谁都别抢）

被分配出去的格子是**预留**的：里面只能放该类别的东西，其它物品（泥土、面包、
别人掉的枪）会被挪到没被预留的格子，没空位就退到背包 9-35。

```
第 1-4 格   主武器 / 副武器 / 近战 / 投掷物
第 5 格     C4（WBD 的 c4-slot）
第 6-7 格   功能道具
第 8 格     自由位（没被预留的快捷栏格子）
第 9 格     商店绿宝石
```

执行顺序：先清场（把不该在这格的挪走）→ 再让各分类归位 → 最后配件进背包。

### 功能道具（`utility` 类别）

拆弹器、医疗包这类东西**不该占前四格**（那是主武器/副武器/近战/投掷物的位置）。
在 `item-categories.yml` 里给它们划好落点：

```yaml
categories:
  utility:
    enabled: true
    slots: [5, 6]     # 0 基，5/6 = 第 6、7 格（默认）
```

- 落在别处（尤其前四格）的功能道具会被挪到 6/7
- 6/7 都被占了就退到背包 9-35 格
- 实在没地方就留在原地——**不丢东西**优先于「不抢前四格」

### 配件（`attachment` 类别）

配件现在是一个**独立类别**，不再是「功能道具」的一部分：

| 配置 | 位置 | 作用 |
|---|---|---|
| `attachment-materials` | `config.yml` | 哪些材质算配件（默认 `TACZ_ATTACHMENT`） |
| `categories.attachment.enabled` | `item-categories.yml` | 关掉就不再自动挪背包 |
| `guns` / `names` / `materials` | `item-categories.yml` | 把某件具体物品归到 `attachment` |

配件**不占快捷栏、不限购**，买到或捡到后自动进背包 9-35 格。

### 配件进背包（`backpack-materials`）

WBD 发商品走的是 `addItem`，而 `addItem` **先填快捷栏**——买一个枪械配件，
占掉的却是 1-9 格，手里正用的枪/投掷物就被挤到背包去了。

`backpack-materials` 里的材质（默认 `TACZ_ATTACHMENT`）买到或捡到后会自动从快捷栏
挪到背包 9-35 格；背包满了就保持原样，不会把东西弄丢。

### 购买兜底（`purchase-safety`）

WBD 发物品时不检查「发不出去」，背包满会直接吞掉。开启后：

- 新物品没进包 → 按缺失比例退款
- 落点格被覆盖 → 把旧物品放回背包（放不下丢脚下）

关掉就恢复 WBD 原样（不退款、不归还）。

### 商店开物品保护（`protect-open-item`）

绿宝石（`shop.yml` 的 `open-item`）不能丢弃、不能换到副手；
被拖走 / 被顶掉 / 被别的插件清掉时，下一秒自动放回固定槽位。
判定读 WBD 自己写的 `item_marker = shop_open`，改 `open-item` 的物品也不影响。

### 按键

服务端能收到的按键**只有**「交换副手」（默认 F）和「潜行」（Shift），
B / 鼠标侧键之类的客户端按键插件看不到。

| 配置 | 触发 |
|---|---|
| `open-key: double-swap` | 450ms 内连按两下 F 开商店（默认） |
| `open-key: swap-hands` | 单按 F |
| `open-key: double-sneak` | 350ms 内连按两下 Shift |
| `open-key: sneak-swap-hands` | 潜行 + F |
| `open-key: off` | 只能用绿宝石右键 / `/wbd buy` |

主菜单的快捷键由 `modules.menu.open-key` 控制，默认 `sneak-swap-hands`（Shift+F），
和商店按键互不冲突。

### 权限

| 权限 | 作用 | 默认 |
|---|---|---|
| `wbdaddon.use` | 基础命令 | 所有人 |
| `wbdaddon.admin` | 重载、模块管理 | OP |
| `wbdaddon.loadout.bypass` | 绕过槽位限制（**默认不授予**，以前是 OP，管理员会因此看不到守卫效果） | 无 |

## 四之二、武器名转换表（`weapon-names.yml`）

击杀播报里的 `%weapon%` 默认是 GunId 自动转换的名字（`tacz:ak47 → AK 47`、
`tacz:ak47 → AK 47`）。想要「AK-47」这种名字，改 `weapon-names.yml`：

```yaml
items:
  "tacz:ak47": "AK-47"
  "ak47": "AK-47"        # 省略命名空间也可以
```

- 首次启动会自动生成模板，**把 TacZ 里所有 GunId 列出来**，值先填自动转换的名字，
  只需要改右边
- 大小写不敏感；非 TacZ 物品也可以按它的显示名匹配
- 改完 `/wbdaddon reload` 生效
- 生效范围：淘汰播报、回合趣闻里的武器名、`%weapon%` 占位符、`WbdAddonApi#resolveWeaponName`
- 没配的枪保持原来的自动转换，不会变成空

## 四之四、观战第一视角

阵亡后用的是原版观战模式，本模块把它挂到存活队友身上：

```yaml
  spectate-camera:
    enabled: true
    auto: true             # 阵亡后自动跟随
    only-teammates: true   # 只看同阵营
    interval-ticks: 20     # 目标死了/走了，最迟 1 秒内换人
    hud: true              # 顶部「战地记录仪」BossBar（标题：观战谁 + 武器，进度条：他的血量）
    bar-title: "&6战地记录仪 &8| &7观战 &f%player% &8| &e%weapon%"
    bar-color: YELLOW
    key-switch: true       # 鼠标左键/右键切上一个/下一个队友
    death-camera: true     # 全队阵亡时把视角拉到最后一个队友倒下的位置
```

- `/spectate` 切下一名存活队友，`/spectate <玩家>` 直接看某个队友，`/spectate off` 退出
- **左键 = 上一个队友，右键 = 下一个队友**（250ms 防抖）
- **阵亡瞬间先看自己倒下的地方 1.5 秒**（`death-hold-ticks: 30`），再自动切到最近的队友，
  给观战者一个缓冲；设成 `0` 就是原来的「一死立刻切人」
- **看不到队友手里的枪**是原版观战模式的限制（不渲染目标的持物与手部动作）。
  绕开它需要让观战者退出观战模式，但 WBD 会持续把阵亡玩家强制设回观战，
  两种写法会互相打架、画面闪烁，所以本模块不碰游戏模式

## 四之三、昵称标签与队友轮廓

这两项都靠「按观察者视角单独处理」，和公告式的全局效果不是一回事：

| 模块 | 效果 | 依赖 |
|---|---|---|
| `name-tag` | 敌人名牌对你看不到，队友照常显示（WBD 的 `[队友]` 前缀保留） | 无（纯计分板队伍） |
| `teammate-glow` | 队友身上有轮廓、敌人没有 | ProtocolLib（逐人发包） |

注意两点：

- **不要同时装 WarZHideName**：两边都靠计分板队伍控制名牌，一个玩家在同一块板上
  只能属于一个队伍，互相 `addEntry` 会把对方踢出去，表现就是名牌闪烁
- `name-tag` 只操作「非主计分板」：WBD 给参赛者单独建板画侧边栏，
  写在主计分板上的队伍对他们不生效

## 五、`reconnect`（断线重联）

两个时间窗，别混淆：

| 配置 | 含义 | 默认 |
|---|---|---|
| `hold-max-seconds` | 比赛最多为他停多久，到点继续 | 60 |
| `pending-max-seconds` | 多久内回来还算重连（自动回原阵营 + 继承经济战绩） | 300 |

- 每队每场 1 次等待，**多人同时掉线共用同一次暂停**
- 等待上限到了就继续打，不影响之后的重连判定
- `auto-rejoin: false` 时只记数据，不自动拉回

## 七、排查

1. 先把对应模块的 `debug: true` 打开，再 `/wbdaddon reload`
2. 日志前缀：`[loadout]`、`[reconnect]`、`[vote]`、`[technical-pause]`、`[round-events]`
3. 常见现象对照：

| 现象 | 先看这里 |
|---|---|
| 买的东西没了、钱也扣了 | `loadout-guard.debug`，看「期望几个 / 实得几个 / 退了多少」 |
| 买刀没替换、锁不到第 3 格 | 刀的类别有没有识别成 `melee`（`gun-overrides`） |
| 商店绿宝石不见了 | `protect-open-item` 是否开着；看槽位是否和 `c4-slot` 冲突 |
| 暂停后回合还在走 | `technical-pause.freeze-timers`；反射是否失败（看启动日志） |
| 掉线没等重连 | 该队本场是否已经用过名额；是否在 `LIVE/FREEZE/ROUND_END` 掉线 |

## 八之二、管理员面板（`/wbdaddon admin`）

权限 `wbdaddon.admin`，箱子界面：

| 按钮 | 作用 |
|---|---|
| **强制开局** | 选一张地图立刻开战：跳过大厅等待，倒计时压到 1 秒。两边都有人时正常开局；**只有你一个人时进入「单人测试模式」**——锁住回合自动结算，不会因为对面没人直接判负 |
| **本回合强制胜利 / 失败** | 按**你所在阵营**判定：你在这局是 T，点胜利就是 T 赢下本回合；失败就是对面赢 |
| **数据管理 → 清除玩家数据** | 列出在线玩家，`Shift + 左键` 清掉某人的生涯数据（K/D、下包拆包、场次、胜场） |
| **数据管理 → 清除比赛记录** | 列出比赛历史，`Shift + 左键` 删掉某一场 |

实现上走 WBD 自己的 `startCountdown()` / `endRound(Team, RoundEndReason)`（反射），
所以强制结算照样记账、发钱、广播，不是硬改状态。
破坏性操作都要求 `Shift + 左键`，防手滑。

**单人测试模式**：`roundEndingLocked` 被置为 true，WBD 的自动结算全部失效
（包括「某队人数为 0」和回合计时到点）。想结束这一回合，用面板的
「本回合强制胜利 / 失败」——它会临时解锁、正常结算、再由下一回合重新锁上。
有第二名玩家进场后自动退出测试模式。
