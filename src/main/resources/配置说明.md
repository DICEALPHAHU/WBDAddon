# WBDAddon 配置说明

> 这份说明随插件一起打包，首次启动时会释放到 `plugins/WBDAddon/配置说明.md`。
> 它比 `config.yml` 里的注释更完整：讲清每个模块**为什么**要这么配、**什么情况下需要改**，
> 以及换一台服务器时需要重新核对哪几处。

---

## 一、安装与依赖

| 项目 | 要求 |
|---|---|
| 服务端 | Paper / Spigot / Arclight 1.20+（已在 Arclight 1.20.1 Forge+Bukkit 混合端实测） |
| Java | 17+ |
| 硬依赖 | **WarZBombDefuse**（没有它插件不会加载） |
| 软依赖 | **TacZSpigotBridge**（枪械相关功能需要；缺失时 `loadout-guard` 自动跳过，其余模块照常工作） |
| 可选 | PlaceholderAPI、JourneyMap、WBDTeamDeathmatch |

`plugin.yml` 里已经把 WarZBombDefuse 写成 `depend`，所以不用手动排序加载。

## 二、模块总览

所有模块都在 `config.yml` 的 `modules:` 下面，每个都有 `enabled: true/false`，
改完执行 `/wbdaddon reload` 生效，不需要重启服务器。

| 模块 id | 名称 | 一句话 |
|---|---|---|
| `kill-reports` | 击杀报告 | 替换淘汰消息，回合结束给每人发自己的伤害统计 |
| `match-status` | 比赛状态显示 | 顶部显示双方存活人数；下包后 BossBar 倒计时 |
| `bomb-defuse-sound` | 拆弹声音提示 | 拆弹过程播放带方位的滴答声 |
| `arena-food` | 竞技场饥饿锁定 | 饥饿恒定，跑速稳定、不自然回血 |
| `arena-effects` | 药水效果清理 | 进场 / 每回合清空药水效果 |
| `position-backup` | 进场位置兜底 | 记录进场前位置，重启后补传 |
| `arena-drops` | 阵亡掉落 | 阵亡掉枪，C4 可落地 |
| `team-armor` | 队伍护甲 | 染色皮革甲做阵营区分，护甲值抵消为 0 |
| `loadout-guard` | 装备槽守卫 | 武器分类 / 限购 / 固定槽位 / 购买兜底 / 开商店按键 |
| `freeze-countdown` | 冻结倒计时音效 | 冻结最后几秒的「哒」声 |
| `menu` | 主菜单 | `/wbda` 或 Shift+F 的箱子菜单 |
| `vote` | 比赛投票 | `/vyes` `/vno` 表决，四种投票事项 |
| `reconnect` | 断线重联 | 掉线守下一回合，重连继承数据 |
| `round-events` | 回合事件 | 回合开始清场、上半场最终局、赛点提示 |
| `round-summary` | 回合结算展示 | 胜方 + MVP + 回合趣闻 |
| `technical-pause` | 技术暂停 | `/pause` 和 `/wbdaddon pause` |
| `journeymap-bridge` | JourneyMap 桥接 | 队伍同步到原版计分板队伍 |

## 三、换一台服务器时，**必须核对**的几处

插件本身不写死任何具体物品，全部按 WBD 的 `shop.yml` 和 TacZ 的分类来跑。
但下面三处和服务器环境相关，换环境时最容易出问题。

### 1. 武器分类（`loadout-guard`）

模块按**类别**工作：主武器 / 副武器 / 近战 / 投掷物。
类别来源按优先级：

1. **`item-categories.yml` 分类对照表**（腐竹可编辑，优先级最高）
2. 物品上的 WBDAddon 标签（PDC `loadout`）——认过一次就固定
3. TacZ 的 GunId → TACZ index 里的 `type`（pistol / rifle / sniper / melee …）
4. config.yml 里的旧规则（`gun-overrides` / `*-materials`）作为兼容兜底
5. 都没命中 → 默认 `primary`，并在控制台提示一次

### 分类对照表 `item-categories.yml`

首次启动自动生成，内容抄自当前 `config.yml`，之后**以它为准**。四张表，先命中先用：

```yaml
# 按 TacZ GunId（大小写不敏感，可省略命名空间）
guns:
  "twx:twx_kw": melee

# 按物品显示名（去掉颜色码后比较），适合非 TacZ 物品
names:
  "战术刀": melee

# 按 Bukkit 材质
materials:
  LRTACTICAL_THROWABLE: throwable

# 按 TacZ index 里的 type 兜底
types:
  pistol: secondary
  rifle: primary
```

可选值：`primary` / `secondary` / `melee` / `throwable` / `utility`（不限购）/ `none`（不纳入管理）。
改完 `/wbdaddon reload` 生效，已经打过标签的物品也会因为「对照表优先」立刻改判。

分类结果会写回物品本身（`primary` / `secondary` / `melee` / `throwable` / `utility`），
所以同一把枪不会因为 TacZ 升级、`gun-overrides` 改动而忽然换类别。
标签是「认一次就固定」的，万一认错了（比如先打了标签、之后才补 `gun-overrides`），
用 `/wbdaddon retag` 把背包里的标签洗掉重新分类即可。

**常见坑**：很多近战模组（例如整合包里那 8 把 Apex 刀）在 TACZ index 里被标成
`sniper`，于是被当成主武器，买刀不会替换、也锁不到第 3 格。
解决办法就是在 `gun-overrides` 里补一条：

```yaml
    gun-overrides:
      "twx:twx_kw": melee
```

不知道 GunId 的话，打开 `modules.loadout-guard.debug: true`，买一次就会在日志里
打出它识别到的类别，照着补即可。

### 2. 商品落点（`give-slot`）

WBD 的 `shop.yml` 里每件商品可以写 `give-slot`：

- `give-slot: -1`（大多数商品）→ `addItem` 发放，**背包 36 格全满时物品会被丢弃**
- `give-slot: 0~35` → 直接 `setItem` 覆盖那一格，**原本在那格的东西会消失**

两种情况钱都已经扣了。本插件的 `purchase-safety` 会在扣钱瞬间抓背包快照，
事后发现东西没到手就按比例退款、落点格被顶掉就把旧物品还回去。
**这个兜底对所有 `shop.yml` 通用**，不需要按商品配置。

### 3. 内部字段反射（`technical-pause` / `reconnect` / `vote`）

以下功能依赖 WBD 的内部实现，WBD 大版本升级后可能失效（失效时只会降级，不会崩服）：

| 功能 | 依赖 |
|---|---|
| 技术暂停 / 断线等待冻结回合计时 | `ArenaSession.tickTask` 字段 |
| `/vsdr` `/vmap` 提前结算 | `ArenaSession.endMatch(Team)` 方法 |

启动日志里会明确写「计时器会一起冻结」或「提前结算不可用（反射失败）」，
看到降级提示就说明 WBD 换了实现。

## 四、`loadout-guard`（装备槽守卫）重点说明

这是配置项最多、也最容易被问到的模块。

### 基本规则

- 主武器 / 副武器 / 近战各 1 把，固定到 `slots` 指定的三格
- 投掷物最多 `limits.throwable` 颗，固定到第 4 格
- `slots` 四项必须互不相同，且不要和 WBD 的 `c4-slot`（默认 4）、
  商店开物品槽位（默认 8）撞车，启动时会警告

### 同款与替换

| 场景 | 默认行为 |
|---|---|
| 买同类**不同**武器 | 旧武器按商店价退款，新武器进固定槽 |
| 买同类**同一把**枪 | 取消购买并退款（防止用「买同一把」免费补弹） |
| 买刀 | **直接换掉手里那把**，不退款、不拦截（刀不吃弹药，`melee-always-swap`） |

`same-gun-policy` 可改成 `replace-no-refund` / `replace-refund`。
刀的行为由 `melee-always-swap` 单独控制，设成 `false` 就退回和枪一样的规则。

### 购买兜底（`purchase-safety`）

WBD 发物品时不检查「发不出去」，背包满会直接吞掉。开启后：

- 新物品没进包 → 按缺失比例退款
- 落点格被覆盖 → 把旧物品放回背包（放不下丢脚下）

关掉就恢复 WBD 原样（不退款、不归还）。

### 商店开物品保护（`protect-open-item`）

绿宝石（`shop.yml` 的 `open-item`）不能丢弃、不能换到副手；
被拖走 / 被顶掉 / 被别的插件清掉时，下一秒自动放回固定槽位。
判定读 WBD 自己写的 `item_marker = shop_open`，改 `open-item` 的物品也不影响。

### 按键

服务端能收到的按键**只有**「交换副手」（默认 F）和「潜行」（Shift），
B / 鼠标侧键之类的客户端按键插件看不到。

| 配置 | 触发 |
|---|---|
| `open-key: double-swap` | 450ms 内连按两下 F 开商店（默认） |
| `open-key: swap-hands` | 单按 F |
| `open-key: double-sneak` | 350ms 内连按两下 Shift |
| `open-key: sneak-swap-hands` | 潜行 + F |
| `open-key: off` | 只能用绿宝石右键 / `/wbd buy` |

主菜单的快捷键由 `modules.menu.open-key` 控制，默认 `sneak-swap-hands`（Shift+F），
和商店按键互不冲突。

### 权限

| 权限 | 作用 | 默认 |
|---|---|---|
| `wbdaddon.use` | 基础命令 | 所有人 |
| `wbdaddon.admin` | 重载、模块管理 | OP |
| `wbdaddon.loadout.bypass` | 绕过槽位限制 | OP |

## 四之二、武器名转换表（`weapon-names.yml`）

击杀播报里的 `%weapon%` 默认是 GunId 自动转换的名字（`tacz:ak47 → AK 47`、
`twx:twx_pxbq → TWX PXBQ`）。想要「VK47 平行步枪」这种名字，改 `weapon-names.yml`：

```yaml
items:
  "twx:twx_pxbq": "VK47 平行步枪"
  "tacz:ak47": "AK-47"
  "ak47": "AK-47"        # 省略命名空间也可以
```

- 首次启动会自动生成模板，**把 TacZ 里所有 GunId 列出来**，值先填自动转换的名字，
  只需要改右边
- 大小写不敏感；非 TacZ 物品也可以按它的显示名匹配
- 改完 `/wbdaddon reload` 生效
- 生效范围：淘汰播报、回合趣闻里的武器名、`%weapon%` 占位符、`WbdAddonApi#resolveWeaponName`
- 没配的枪保持原来的自动转换，不会变成空

## 五、`reconnect`（断线重联）

两个时间窗，别混淆：

| 配置 | 含义 | 默认 |
|---|---|---|
| `hold-max-seconds` | 比赛最多为他停多久，到点继续 | 60 |
| `pending-max-seconds` | 多久内回来还算重连（自动回原阵营 + 继承经济战绩） | 300 |

- 每队每场 1 次等待，**多人同时掉线共用同一次暂停**
- 等待上限到了就继续打，不影响之后的重连判定
- `auto-rejoin: false` 时只记数据，不自动拉回

## 六、`vote`（投票）

| 命令 | 范围 | 门槛 |
|---|---|---|
| `/unpause` | 全场 | 全员同意 |
| `/vkick <队友>` | 同阵营 | 除被踢者外全员同意 |
| `/vmap <地图>` | 全场 | 超过 2/3 |
| `/vsdr` | 同阵营 | 全队同意 |

`duration-seconds` 是投票时长，`cooldown-seconds` 是同类投票冷却。
`include-spectators` 决定全场投票是否算上观战者。

## 七、排查

1. 先把对应模块的 `debug: true` 打开，再 `/wbdaddon reload`
2. 日志前缀：`[loadout]`、`[reconnect]`、`[vote]`、`[technical-pause]`、`[round-events]`
3. 常见现象对照：

| 现象 | 先看这里 |
|---|---|
| 买的东西没了、钱也扣了 | `loadout-guard.debug`，看「期望几个 / 实得几个 / 退了多少」 |
| 买刀没替换、锁不到第 3 格 | 刀的类别有没有识别成 `melee`（`gun-overrides`） |
| 商店绿宝石不见了 | `protect-open-item` 是否开着；看槽位是否和 `c4-slot` 冲突 |
| 暂停后回合还在走 | `technical-pause.freeze-timers`；反射是否失败（看启动日志） |
| 掉线没等重连 | 该队本场是否已经用过名额；是否在 `LIVE/FREEZE/ROUND_END` 掉线 |
